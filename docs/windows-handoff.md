# Windows PC での実機検証

クラウドのこのセッションからローカルPCを遠隔操作する接続機能はありません。Windows上でローカル実行できるCodexセッション／ターミナルを開き、このコードを作業フォルダーとして使用してください。ローカルPCをリモート公開したり、資格情報をチャットに貼る必要はありません。

## 引き継ぎ

ZIPを任意の作業フォルダーへ展開し、ルートのREADME.md / AGENTS.md / .agent/PLANS.mdを確認します。クラウド用`.venv`はZIPに含めません。Windows側で作り直してください。既存のユーザーファイルへ上書きせず、空のフォルダーへ展開します。

ローカルセッションへの作業指示:

> AGENTS.mdと.agent/PLANS.mdを読み、観測専用Master Duel AdvisorのWindows実機検証を継続してください。ゲームへの入力／メモリ読取り／注入／通信解析は禁止です。scripts/setup.ps1で環境を用意し、pytestと合成デモを実行した後、ゲームの表示領域だけをsnapshotしてください。実画面で領域を校正し、別の画面でLP・turn・phaseの精度を評価してください。dxcam/MSSを同じ動きのある場面と表示モードで比較し、未測定GPU/drop/物理遅延を測定済みと扱わないでください。実ゲーム精度ゲート未達ならカード認識の実運用へ進まず改善し、結果とDecision Logを更新してください。Executeは人間が行います。

## 実行順

1. Python3.12 / pip / Windows11の確認。`scripts/setup.ps1`、pytest、demo。環境の不具合とコード不具合を分け、失敗時には回帰テストを追加する。
2. 人間がMaster Duelを起動する。ユーザー指定のゲーム表示矩形でMSS snapshot。画像が黒い／違うモニター／DPIで切れる場合は矩形・表示モードを調べる。ゲームの内部へ接続しない。
3. ウィンドウとボーダーレス／フルスクリーンの同条件でdxcam/MSSを比較し、FPS、read time、CPU、未測定項目を保存する。最低10FPS、目標30FPS。GPUや実dropはOSの外部計測などで追加し、値を捏造しない。
4. LP→turn player→phase→turn number→hand countの順に校正し、独立holdoutデータで評価。テンプレート登録画像を評価用画像に再使用しない。
5. LP/turn/phaseの精度が各95%以上かつ十分な既知・未知・negative UIサンプルを確保した後、20–50種のカード画像を追加してカード精度を評価する。
6. リプレイ動画でも同じパイプラインを通す。実カードとUIボタンの対応、対象選択、効果ルール、戦略判断はまだ実装が必要。画面データを得てから限定対応範囲を定義し、候補の合法性を評価する。
7. ライブUIを別ウィンドウで実行し、取得範囲外へ置く。情報が古い／未知の時に推奨が消えること、ゲームに入力しないことを確認する。
