# 開発方針

Windows 11 / Python 3.12 向けに観測専用の Master Duel アドバイザーを開発します。実装前に `.agent/PLANS.md` を読み、変更後は進捗・検証結果・判断を更新してください。

- ゲームへのマウス・キー入力、ゲームメモリの読み取り、DLL 注入、パケット解析、アンチチート回避は禁止です。
- 画面に見えている情報だけを取得します。相手の隠れたカードは推測せず、未知情報は認識元と信頼度を持つ未知値として扱います。
- 取得・認識・状態・ルール・判断・表示を分離します。操作実行はインターフェースのみで、Master Duel 向けの実装を作りません。
- 決定的な画像処理と OCR を優先し、毎フレーム画像 API を呼びません。外部モデルには明示的な利用設定と予算が必要です。
- 再現可能なデータと録画で検証します。合成精度を実ゲーム精度と扱わず、実測なしに Windows 性能や実認識の完了を宣言しません。
- 校正済みの表示中の操作 UI に裏付けられた候補だけを推奨します。部分的な状態で全ルールの合法性を証明したとは扱いません。
- 文書と実装を一致させ、検証済みの機能を報告する前に `python -m pytest` と記載のデモ・評価を実行します。
- 既存の隔離されたチェックアウトを使い、依頼がない限り Git worktree を作りません。
- 説明文、コメント、利用者向けメッセージは日本語にします。識別子、コマンド、JSON キー、機械判定用の値は互換性のため維持します。
- 対戦ルール・カード・テーマ判断では、先に `docs/knowledge/README.md` と該当ガイドを読みます。該当テーマのガイドがなければ公式カードテキストを調べ、判断と出典を `docs/knowledge/themes/` に保存します。Master Duelの現行制限を紙のOCG/TCGと混同しません。

開発依頼によりソース・テスト・依存関係・文書の作成が許可されています。先行する環境セットアップだけの作業とは区別します。

## カード情報のローカル保存規則

- カードの効果・属性を参照する前に `data/card-knowledge.sqlite3` または指定されたカードDBを確認します。未保存ならユーザー指定のYGOPRODeck v7から取得し、必ずローカル保存してから再利用します。`docs/card-knowledge-cache.md` のコマンドとデータ構造を使います。
- 保存済み情報は毎回ダウンロードしません。更新は明示的なrefreshで行い、失敗時も既存の正常なデータを消しません。取得不能は未取得として記録し、連続再要求しません。
- YGOPRODeckのパスコードとKONAMI IDを区別します。新しい対応付けはID種類を明示し、日本語名は同じKONAMI IDの公式日本語ページと照合します。曖昧検索の最上位を自動採用しません。
- YGOPRODeckの英語原文、取得日時、URL、未加工JSON、ハッシュを保存します。日本語訳は別データとし、英語を日本語確認済みとして扱いません。OCG/TCGの規制情報をMaster Duelへ適用しません。
- 対戦中の不足取得はBackgroundKnowledgeに任せ、画面認識・10秒判断を通信待ちにしません。画像・画面・個人情報をAPIに送信しません。
