# 暫定展開ルールの実機テスト（2026-10-05）

## 結果

実画面を読み、Computer Useで操作し、超雷龍－サンダー・ドラゴンの特殊召喚まで完了した。これは画面確認を伴う補助操作テストであり、agent-loopによる無人完走ではない。対戦終了・勝敗は未検証。

最終確認画面はTurn 1 / Main1、双方LP8000。自分の場に輝白竜 ワイバースター（1700/1800）と超雷龍（2600/2400）、手札4枚。選択ダイアログは閉じており、この状態で操作を終了した。

## 実画面で確認した流れ

1. サンダー・ドラゴンの手札効果を発動し、同名2枚を手札に加えた。
2. 混沌領域で雷電龍をコストとして墓地へ送り、ワイバースターをサーチした。
3. 墓地の雷電龍を除外してワイバースターを特殊召喚した。
4. 除外された雷電龍の効果で雷鳥龍をサーチした。
5. 雷鳥龍の手札効果で除外中の雷電龍を特殊召喚した。
6. EXの召喚候補から超雷龍を選び、雷電龍をリリース、攻撃表示と配置位置を確定した。
7. 演出後、超雷龍が場に残り、通常のMain1画面へ戻ったことを確認した。

前半のフリーマッチでは増殖するGの発動とサンダー・ドラゴンのサーチを確認したが、途中で操作が中断した。再開時の相手表示は「滅びゆく世界」で盤面も異なっており、上記の召喚完了は前半と別の対戦。現在の対戦モードをフリーマッチと断定しない。

## ルール評価ログと限界

`scripts/validate_visual_assisted.py` から実際のRulePlannerを個別に評価し、`evaluation/free-duel-visual-assisted.jsonl` に8件を記録した。6件は推測による候補採用、2件はprompt不一致で停止した。

- 増殖するG: `chain.response` で `action.maxx` がprompt条件により停止。
- 超雷龍: `extra.summon_select` で `action.colossus` がprompt条件により停止。

停止箇所は画面確認による補助操作で進行した。推測モードだけではダイアログの対応不足は解消しない。ログの状態・候補は画面を見て与えた値で、自動認識結果ではない。confidence=1.0は認識精度100%を意味しない。各実行でPlannerを生成し直すため、連続操作時の使用済み効果履歴も検証していない。

記録された判断処理だけの所要時間は約0.034〜0.095ms。ただし画面取得、画面解釈、モデル応答、ツール往復、入力、演出待ちを含まない。実機での10秒期限達成・期限時の強制選択・全画面対応の合格判定には使えない。今回のゲームはタイトルバー付きウィンドウで、全画面表示の受入テストではない。

## 次に必要な改善

1. チェーン応答・EX召喚選択を、通常画面での発動開始とは別の操作段階として登録する。prompt制約を一律解除しない。
2. コスト・サーチ・蘇生対象・素材・確定・表示形式・配置位置の各画面を認識し、対応する操作と結果確認を接続する。
3. 同一Plannerを維持した連続実行で、効果使用履歴と重複入力抑制を検証する。
4. 実画面向け校正を整備したagent-loopで、判断待ち込み時間と入力までの時間を別々に計測する。10秒到達時に最新候補を選ぶ経路も実測する。

今回、展開エンジンのソースは変更していない。既存の206成功・4スキップは以前の検証結果で、今回再実行した結果ではない。実ゲーム精度ゲートは合格へ変更しない。
