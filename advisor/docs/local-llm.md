# ローカルLLM接続

Ollamaの取得済みモデルを、既存の例外判断へ接続します。APIキー・ChatGPTログインは不要です。Ollama本体とモデルは別途必要です。自動インストールや自動モデル取得は行いません。

Ollamaを起動し、`ollama list`で取得済みモデル名を確認してください。既存の校正済みrun/agent-loopコマンドに次を追加します。MODEL_NAMEは実際のモデル名で置き換えます。

```powershell
--local-model MODEL_NAME --llm-timeout 3 --llm-cooldown 2 --llm-max-calls 30
```

`--chatgpt`とは併用できません。既定接続はhttp://127.0.0.1:11434で、ループバックHTTPのみを許可します。プロキシとリダイレクトは利用しません。

構造化盤面と表示された候補だけを送り、画像は送りません。JSON Schemaを指定し、思考出力を無効化、温度0、コンテキスト4096、生成上限192トークン、モデル保持30分を指定します。設定の対応状況はモデルとOllamaの版に依存します。初回のモデル読み込みは遅くなるため、使用前に短い問い合わせで起動しておいてください。

期限超過・未完了・不正JSON・盤面変化・候補不一致・低信頼度のAI回答は採用しません。認識開始から判断は最大10秒の期限を持ち、期限では最新の許容候補のうち認識信頼度が最高の行動を強制選択します。LLMの予算や再要求制限で要求できない場合も待たずに選択します。候補がない・古い・信頼度不足の場合は入力しません。`--llm-timeout` は10秒以下です。詳細は[判断の10秒上限](fast-loop.md)。ルールで処理できる場面は従来どおりLLMを呼びません。モデル自身のconfidenceは正しさの保証ではなく、対戦判断の精度検証が別途必要です。

ゲームと共有するVRAMを考慮してください。1秒の期限指定は可能ですが、間に合わない応答は破棄されます。LLM接続は未作成の画面校正やデッキ・展開設定を補いません。

高速化のため返答は候補番号と信頼度の2項目に限定します。候補番号を検査して元の候補へ戻し、既存の盤面・時刻・候補照合を通します。自由な操作文字列を生成させません。

2026-10-04、RTX 3060 Ti 8GBとOllama0.35.1、qwen3:4b-instructで単一合成候補を測定。モデルは3.2GB、100%GPU、コンテキスト4096。従来の全文JSONは初回約76秒、読み込み後約0.98〜1.01秒。候補番号方式は初回442ms、その後225〜243msで、5回すべて候補一致。繰り返した同じ入力でキャッシュが効く接続テストです。複雑な実盤面・独立した判断精度・クリック速度を示す値ではありません。結果はartifacts/local-inference-compact-validation.json。

API仕様: https://docs.ollama.com/api/chat

## このプロジェクトのポータブル版

advisorフォルダーで `./scripts/start_local_llm.ps1` を実行して起動します。Ollama本体は親フォルダーのtools/ollama、モデルはtools/ollama-modelsに置きます。Windowsの自動起動は登録しません。

取得済みモデルは次で確認します。

```powershell
..\tools\ollama\ollama.exe list
.\.venv\Scripts\python.exe -X utf8 scripts/validate_local_inference.py --model qwen3:4b-instruct
```

検証は単一の合成候補に対する接続・JSON・時間の確認です。初回と以降の時間を記録します。実際の対戦判断精度やクリック速度の検証ではありません。
