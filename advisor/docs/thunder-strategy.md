# 提供デッキの展開ルール

## 暫定推測モード（2026-10-05追加、現在の設定）

ユーザーの「一旦推測で対応」の指定により、実行JSONの `inference_mode` を `provisional` に変更した。
以下の厳密な条件表に対し、認識済みの登録操作が表示されていることを根拠に、未確認のfacts、
手札/盤面の必要カード、素材集合を条件成立と仮定できる。観測データそのものは書き換えない。
確認済みのfalseや不適合素材は拒否する。未登録ボタン、古い/低信頼度の操作候補、異なるプロンプト、
未知のターン側/フェイズ、演出/終了、操作確認待ちには推測を適用しない。

`plan.assumptions` に推測した条件、`plan.inferred_used` に暫定使用履歴を保存する。
通常判断の状態名は `deck_rule_inferred`。10秒期限では推測を含む許容候補から強制選択し、推測根拠はplanに残す。
推奨のconfidenceは引き続き操作UIの認識信頼度であり、推測の正解率・勝率ではない。

発動/特殊召喚を送った時点で対応する使用枠を暫定消費し、通常召喚の送信も記録する。
ヴェルテのコピー送信後は暫定的に特殊召喚を止める。クリック失敗でも同じターン内で自動解除しない。
確認できたターン切替または対戦終了で暫定履歴を消す。途中起動時の過去の使用状況は未確認として推測する。
これにより実行を進められる一方、成立しない行動を選ぶ/可能な行動を見送る場合がある。

以前と同じ `--plan-book data/decks/thunder-dragon-review/strategy-book.json` で読み込める。
厳密判定へ戻す場合はJSONの `inference_mode` を `strict` にする。
生成スクリプトも暫定モードを出力する。実画面のボタン校正がない場所へ座標を推測してクリックする機能は含まない。

以下は厳密モードの基準仕様。暫定モードでは上記の未確認条件を緩和する。

作成日: 2026-10-05。対象はサンドラのメイン40枚・EX14枚、35種類。
実行用は `data/decks/thunder-dragon-review/strategy-book.json`、条件の全一覧は
[94件の条件表](thunder-strategy-rules.md)。生成元は `scripts/build_thunder_strategy.py`。

これは35種類を扱う条件付きの戦略ルールです。全対面・全チェーンの完全解探索器ではありません。
優先度は人手で定めた方針で、勝率ではありません。現行Master Duelの制限や裁定をすべて実機検証したものでもありません。
旧サンプルの「雷電龍が場にいれば超雷龍を出す」という不十分な判定は使いません。

## 判断の順序

1. 終了・演出・操作確認中なら新しい操作を出さない。
2. 現在のターン・フェイズ・正確なプロンプト・表示候補を確認する。
3. 発動可能な窓、コスト、対象、残りデッキ、効果使用履歴、召喚制限を検査する。
4. 素材集合を個体単位で検査する。同じカードを二度数えない。
5. 誘発/破壊代替/妨害を優先し、通常時は初動→展開→融合→後続→セットへ進む。
6. 入力後は画面を再認識して最初から評価。画面遷移だけで効果が解決したとみなさない。

優先度は最大1000。破壊代替1000、妨害970〜990、誘発/選択880〜950、超雷龍850、融合820、雷鳥龍800、
通常初動730〜740、カオス展開620〜650、ヴェルテのコピー300、罠セット180。
条件が揃った候補だけを比較する。固定順位には戦略上の限界があるため「常に最適」とはしない。
10秒期限でもこの検査を通過した候補だけを強制選択する。禁止・未知の候補をLLMや汎用判断へ渡さない。

## 基本ルートと分岐

以下は必要札・未使用効果・対象・ゾーンが全て確認できた場合の方針。UIを確認せず連続クリックする台本ではない。

|初動|進行|到達点と中断条件|
|---|---|---|
|孤高除獣＋雷獣龍|孤高を召喚→手札雷獣をコスト除外→デッキ雷電を除外→雷獣で雷族展開、雷電で雷鳥確保→雷鳥で除外/墓地雷龍を蘇生|雷鳥の手札発動を確認して超雷龍。雷獣/雷電の手札効果を既に使っていればこの線は不成立。誘発の処理順は実際のチェーンUIに従う|
|太陽電池メン＋雷鳥龍|太陽電池メン→雷獣等を墓地へ→雷鳥で蘇生→トークンを生成|太陽電池メンや蘇生雷族を超雷龍のリリースにできる。トークンは超雷龍のリリースにできない。デッキから墓地へ送った雷獣だけでは誘発しない|
|サンダー・ドラゴン＋雷族の場への供給|手札効果→同名確保→雷源龍などを通常召喚、または別の方法で非融合雷族効果を供給|手札発動を確認して超雷龍。サンダー・ドラゴンのサーチだけで場が生まれたとは扱わない|
|混沌領域＋光/闇|手札を墓地へ送る→反対属性の小型カオス竜サーチ→墓地の対応属性を除外して特殊召喚→ストライカー→相方サーチ|各小型竜の特殊召喚は名前ごと1回。混沌領域の手札コストは除外ではなく墓地送り。雷龍の墓地誘発を誤って起こさない|
|闇の誘惑＋闇雷龍|2ドローを確認→雷獣または雷電を効果で除外→未使用の誘発へ|ドロー内容を先読みしない。闇を持たない発動を基本方針では避ける。除外選択はドロー後の実手札で再判断|
|場/墓地/表側除外に融合素材|雷龍融合→雷神龍なら雷龍3体、超雷龍なら元祖サンダー・ドラゴン＋雷族|手札は雷龍融合の素材範囲に含まれない。後続と破壊代替用墓地を残す。雷神龍用の雷源龍等を手札に温存|
|クロシープ＋融合可能|リンク先を確保→その先に融合を特殊召喚→レベル4以下を蘇生|融合を指している事実とリンク先への特殊召喚イベントが必要。単に2体が場に並んだだけでは使わない|
|効果モンスター2体＋雷龍融合がデッキにある|他の特殊召喚を終える→ヴェルテ→2000LPを払ってコピー|解決後の特殊召喚は禁止。墓地送りされた雷龍融合のサーチは当ターン不可。コピーに関する例外裁定は実際の使用可否表示を要する|
|リンク素材と突破札が揃う|ユニコーンで戻す→アクセスコード等で突破|リンク数だけでなく名前・効果モンスター条件・必要体数を検査。確定リーサル計算は未実装|

黄金櫃は提供デッキにないため、以前の一般ガイドの黄金櫃ルートをこのルールには登録していない。

## 素材、コスト、選択

- 雷源龍・雷電龍・雷鳥龍・雷獣龍はそれぞれ名前単位で手札効果と誘発効果が共有制限。
  使用と発動成功/効果解決を混同しない。無効時も使用履歴をリセットしない。
- 太陽電池メン、混沌領域、雷龍融合などの別々の効果は個別の使用枠。
  `instance.*` の制限はカード個体ごとに管理し、同名全体の制限と混ぜない。
- 雷神龍の別法召喚で超雷龍を失う場合、後続の雷神龍除去が有効だと確認できた時だけ採用する。
- 融合素材は墓地/除外から戻す候補を優先しつつ、破壊代替用の墓地と蘇生先を残す。
  素材検査器は集合の適格性を検査するが、全素材組合せの最適化は行わない。
- リンクモンスターはリンク数または1として数える。リンク3を2として使わない。
  ヴァレルソードは3体以上、アクセスコードは2体以上の効果モンスターが必要。
- 常夏/轟雷機龍には雷族トークンを使える。ヴェルテ/アクセス/ヴァレルソードには使えない。
- 剛鬼デストロイ・オーガは剛鬼素材が必要。ドライバーの通常召喚とともに基本戦略では無効。
  ストライカーのブートセクター/ヴァレット関連効果もデッキ内対象がないので登録しない。
- 超雷龍と雷神龍は指定の召喚方法のみ。死者蘇生や雷鳥龍の蘇生候補にしない。
- 除外対象、破壊対象、手札コストは個体を識別する。同名の複数候補が区別不能なら選ばない。
- タイタンの除去は手札雷族効果へ直接チェーンできる窓が必要。轟雷機龍の効果適用を手札発動に数えない。
- 対象耐性付与は既に行われた対象選択を取り消す効果ではない。天雷震龍を万能カウンターにしない。

## 相手ターンと妨害後

手札誘発は実際の公開チェーンが条件に一致した場合だけ使う。γは自分モンスターなし、ドライバーと空き2枠を確認。
泡影の手札発動は自分のカードがゼロの時。神の宣告はモンスター効果を無効にする札として使わない。
雷神龍の手札効果連動、常夏のリンク先蘇生、雷龍の破壊代替を別の窓として処理する。

妨害・対象消失・盤面変化のたびに再評価し、未使用効果と残った手札/墓地/除外から復帰する。
元のルートを続けるために「成功したはず」のカードを補完しない。
特殊召喚封じ・効果無効・対象耐性・除外禁止等は `window.*`、`summon.allowed`、個別対象条件で拒否する。
相手の未知の手札や伏せ札を決め打ちしない。

## 状態データと画面接続

`GameState.facts` は `Observation[str]`。値、認識元、信頼度、取得時刻を必須の根拠とする。
全ルールで現在フレームと同じ時刻かつ信頼度0.98以上が必要。キーがない場合は不成立。

- `window.<rule-id>=open`: 対応する実際の発動/選択窓。単なるカード画像の存在ではない。
- `unused.<effect-group>=true`: 未使用が履歴から確認できる時だけ。未知を未使用としない。
- `hand_thunder.activated=true`: 当ターンの手札雷族発動履歴。
- `summon.allowed=true`: 現在の特殊召喚制限等と該当召喚を照合済み。
- `fusion.target=13923/13924`: 選ぶ融合先。
- `GameState.material_sets[method]`: `Observation[list[Material]]`。個体ID、現在名、種族、効果/融合/トークン区分、
  レベル、リンク数、場所、表裏、雷龍/剛鬼所属を含む。候補集合と確定UIで同じ検査を再実施する。
- `selection.<method>.valid=true`: 素材集合に加えて、現在の選択個体・コスト支払い・召喚先を照合済み。

`Perception` に `fact.<key>` のtemplate領域を追加すると、認識値がfactsへ入る。
画面に直接出ない履歴は、イベントを欠落なく検証する追跡処理が必要。現在その追跡処理は未実装。
素材個体集合の自動抽出も未実装で、検証済み状態を与えるAPIと検査器を用意した段階。
**既存の全画面校正だけでは新ルールの必要情報は揃わない。実機の完全自動展開は未完成。**
現在は不足したキーをsnapshotの `plan.blocked` に出す。便宜的に全条件trueを固定登録してはいけない。

既存コマンドのプラン指定を次へ変更すると読み込める（ほかの実画面校正・DB引数はそのまま）:

```powershell
--plan-book data/decks/thunder-dragon-review/strategy-book.json
```

旧形式のplan-bookは互換維持。新形式は未登録の攻撃/フェイズ終了/キャンセル等も自動選択しない。
残る作業は、全プロンプトと素材個体の認識、使用/召喚履歴の追跡、対象選択の網羅、
バトルとダメージ計算、個別対面/チェーン裁定、実録画・実機の受入検証。

## 混沌領域から超雷龍までの画面操作（2026-10-05）

`data/decks/thunder-dragon-review/colossus-route.json` は、前回の補助付き実機テストを基にした34操作の専用手順。
生成元は `scripts/build_colossus_route.py`。汎用94ルールとは別の `--plan-book` として選択する。
初手の混沌領域と雷電龍が揃い、所定の空きゾーンが使える場合を対象とする。
このルートでは雷鳥龍の手札効果が超雷龍の手札雷族発動条件を作るため、最初のサンダー・ドラゴン発動を必須にしていない。

- `additional_prompts`: 既存の増殖するGに `chain.response`、超雷龍に `extra.summon_select` を追加。その他の未登録画面は許可しない。
- `follows`: 直前に確認できた操作ID。クリック送信だけでは次の手順を許可しない。
- `observed_facts`: 選択したカード・枚数・場所・空きゾーン・チェーンの所有者など。暫定モードでも推測で補わない。
- `expected_prompts` / `expected_facts`: 操作後に確認する画面とカードの状態。入力失敗、未知画面、演出だけでは進行しない。
- `last_completed`: プラン状態に表示する確認済み操作。中断時には消し、同じターンの使用済み効果は保持する。

自分の効果にチェーンしない分岐は `chain.owner=self` と発動カードの画面証拠を要求する。
相手の割込みや対象消失に対する復帰分岐、別の手札・配置への一般化は未実装。
固定の待ち時間や記憶した座標を順番に実行するマクロではない。

画面校正は手順定義と別に必要。現在の `artifacts/live-validation/calibration.json` は以前の限定計測用で、
新手順の検査では54項目が不足した。次のコマンドはゲーム入力なしで不足一覧を保存し、未完なら終了コード2を返す。

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/audit_colossus_route.py --calibration artifacts/live-validation/calibration.json
```

一覧は `evaluation/colossus-route-readiness.json`。`ui.prompt` の15種類の識別値、34操作の候補と位置、
選択対象などの `fact.*`、ターン/フェイズ/演出/終了の参照画像を校正する。
手札枚数でカード位置が変わるため、今回の画面座標を全手札へ固定適用しない。
同じ外観に異なるpromptラベルを付けると識別できないため、カード詳細・選択欄・直前に確認した操作を使う接続も必要。
現在の認識器はその接続や移動するカードの汎用検出を自動生成しない。

不足したまま `colossus-route.json` を起動すると、入力開始前に不足領域名を返す。
構造検査に通っても実画像での識別精度を保証しない。専用手順の無人実機完走と10秒期限の実測は未完了。

検証: 同一Plannerでチェーン選択あり/なしを連続評価し、実際のPipeline/AgentLoopと模擬入力で34操作の確認完了を検証。
これは認識済みの合成状態を使うテストで、実ゲーム認識ではない。未知/誤った選択の確定拒否、期限時の拒否維持、
演出中の進行禁止、効果重複抑制、中断とターン切替も検証した。全221成功・4スキップ。
合成デモ4/4一致、`evaluation/ui-route-synthetic.json` の実機精度ゲートはfalse。
